#### Task 8.7: Dashboard and external message surface

**Objective:** Build the main dashboard in `client/` and the narrow `externally_connectable`
message path that feeds it from the extension. The server remains stateless and the dashboard never
gets a general storage read or onboarding preferences.

**Dashboard model:**

```typescript
type DashboardSummary = {
  recoverableValue: number;
  savedValue: number;
  openItems: Array<{
    itemId: string;
    title: string;
    price: number;
    returnBy: string | null;
    daysRemaining: number | null;
  }>;
};
```

**Instructions:**
1. Add the build-time `DASHBOARD_ORIGIN`, defaulting to `http://localhost:3000` in development and
   failing a release build when no concrete production origin is provided.
2. Add the external message request/response union. The only response is `DashboardSummary`; do
   not expose `PREFERENCES`, raw storage, retailer DOM, credentials, or driver mutation commands.
3. In the extension-side external-message handler, read `ORDER_ITEM` and `RETURN_REQUEST` entities
   and compute the response fresh for each dashboard render request: `recoverableValue` from
   currently returnable items, and `savedValue` from successful terminal returns (`LabelPrinted`,
   `DroppedOff`, or `HandedOff`; exclude `Aborted`). Return only the resulting `DashboardSummary`.
   Rank `openItems` by days remaining using the existing ranking function; do not persist running
   totals or expose per-item return state.
4. Render the main dashboard with the two money figures and the ranked open-item list. If no
   extension is installed or the external message is unavailable, show an install prompt.
5. Add tests for extension-side summary calculation, including successful and aborted terminal
   states, ranking, empty data, absent extension, and rejection of an unknown or mutation message.
   Add a browser acceptance step for a real dashboard-to-extension read.
6. Reference: requirements FR-3.2.2, FR-3.6.3 and §5.2; high-level design §3.3/§6.7; low-level
   design §1 and §7.2; decision D28.
