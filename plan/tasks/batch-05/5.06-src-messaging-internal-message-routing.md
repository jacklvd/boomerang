#### Task 5.6: `src/messaging/` — internal message routing

**Prerequisites:** Task 4.12, Task 2.4
**Conflicts with:** None
**Parallel with:** Tasks 5.1–5.5
**Package:** `extension/src/messaging`

**Objective:** Define the enumerated message set and route it between the popup, the content script
and the worker.

**The dashboard half is in scope again** (2026-09-01, decision D28). It is read-only and enumerated;
it must not become a general-purpose storage bridge.

**Instructions:**
1. Create `extension/src/messaging/messages.ts` with a discriminated union covering every message the
   popup and content script can send. An unknown type is rejected, not forwarded.
2. Create `extension/src/messaging/router.ts` with an `on_internal` handler.
3. Add an `on_external` handler for the dashboard. Verify `sender.origin` against `DASHBOARD_ORIGIN`
   before dispatch, and expose only the dashboard summary request/response. `externally_connectable`
   is a delivery filter, not an authorisation check.
4. Unit tests: a valid internal message dispatches; a valid dashboard summary request from the
   configured origin dispatches; an unknown type or wrong-origin external message is rejected
   without dispatch.
5. Reference: Low-Level Design §3.4, §7.2; requirements FR-3.6.1, FR-3.6.3, NFR-6.5; decision D28.

**Verification:**
- `cd extension && bun run test tests/messaging`
