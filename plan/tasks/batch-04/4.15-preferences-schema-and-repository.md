#### Task 4.15: `PREFERENCES` schema and `PreferencesRepository`

**Objective:** Define and persist the retailer-agnostic onboarding preferences in the extension's
client-side store. This is a required storage schema, not an untyped popup object and not a server
database record.

**Schema:**

```typescript
type Preferences = {
  return_address?: Address;
  preferred_return_mode?: "dropoff" | "pickup";
  has_printer?: boolean;
};
```

**Instructions:**
1. Create `extension/src/storage/preferences.ts` with `get`, `set`, and `clear` over one storage
   key, following `AddressRepository`'s singleton shape.
2. Validate reads defensively. An absent or corrupt record returns unset preferences; it must not
   invent a default or throw during popup startup.
3. Export the repository and `Preferences` type from the existing storage barrel. Do not send this
   record to the server and do not expose it through dashboard messages.
4. Add unit tests for a complete round trip, skipped onboarding, corrupt data, and clearing an
   absent record.
5. Reference: requirements §2.2 and FR-3.0.1–FR-3.0.3; high-level design §4.2; low-level design
   §3.4; decision D27.

**Verification:**
- `cd extension && bun run test tests/storage/preferences.test.ts`
