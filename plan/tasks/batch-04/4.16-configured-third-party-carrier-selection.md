#### Task 4.16: Configured third-party carrier selection

**Objective:** Keep USPS as the first supported carrier while making the carrier boundary extensible
for UPS and other retailer-dependent options. A retailer's available return method determines its
carrier; the server verifies that carrier against `SUPPORTED_PICKUP_CARRIERS` before pickup work.

**Instructions:**
1. Preserve the existing USPS adapter as the first concrete implementation. Do not make USPS the
   only valid value in the carrier protocol or pickup service.
2. Add configuration parsing and startup validation for `SUPPORTED_PICKUP_CARRIERS` and map each
   enabled carrier to its adapter and credential loader. An unsupported or unconfigured label
   carrier must fail closed with `wrong-carrier-label`.
3. Keep Amazon Door Pickup as a retailer-provided option unless an explicit Amazon integration is
   later added. The driver may present it with its price, but the server must not pretend it can
   schedule Amazon logistics through a generic third-party carrier API.
4. Add tests covering USPS as the first supported carrier, an additional configured adapter, an
   unsupported label carrier, and a retailer option with no brokered pickup path.
5. Reference: requirements FR-3.3.4–FR-3.4.8 and §5.1; high-level design §3.2/§3.4; decision D26.
